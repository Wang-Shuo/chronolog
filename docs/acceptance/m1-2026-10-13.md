## 3. 真实数据副本演练

输入为本地历史运行 `full-backfill-2026-08-01/01-collected/releases.json`，包含三个产品的 648 条 Release。该文件被 Git 忽略，并非本次从官方源实时采集；本验收不证明当前来源可用性或内容新鲜度。

执行 [verify_m1_replay.py](../../tests/manual/verify_m1_replay.py)：

```bash
.venv/bin/python tests/manual/verify_m1_replay.py \
  --collection _pipeline/full-backfill-2026-08-01/01-collected/releases.json \
  --output /tmp/chronolog-m1-verified-20261013
```

脚本拒绝已有输出目录，复制实际 Vault 后依次执行：

1. 全量回放并对账，生成可独立重建的 Markdown 事实字段。
2. 添加人类笔记和 `human_overrides`，删除副本旧 `_pipeline/`，仅输入每产品最新一条 Release。
3. 再次重跑同一增量，比较正式 Markdown 全集合内容摘要。
4. 将评估日期从 2026-08-01 推进至 2026-10-13，基于历史快照生成暂存告警以产生真实写入；在第三次写入注入异常，核对全部文件恢复。该告警仅为离线故障演练，不发布或声称反映当前产品状态。
5. 恢复后按原评估日重跑，检查无重复、笔记保留、源仓库未变。

可携带结果保存为 [m1-replay-results.json](m1-replay-results.json)，包含输入 SHA-256、执行代码 SHA-256、各步骤计数及回滚断言。单次 manifest 与校验报告保存在临时输出的 `evidence/`；摘要已复制进本目录，后续不依赖临时目录才能了解验收结论。

## 4. 构建验证与范围说明

```bash
npm run build -- \
  --directory /tmp/chronolog-m1-acceptance-20261013/vault \
  --output /tmp/chronolog-m1-acceptance-20261013/site
```

构建成功，解析 2,469 个 Markdown，输出 2,538 个文件。最终回放副本与该构建输入的全部 Markdown 文件 SHA-256 也已逐一核对相同。只有上游 Node `punycode` 弃用提示，无构建错误。本次未更新源仓库的 Products/Releases/Changes/Themes/index，也未部署站点。

边界：文件逐一原子替换，整个多文件 Vault 不提供同时可见的文件系统快照；构建应在管线成功退出后开始。进程被强制终止时，journal 会在下次执行或 `--recover-only` 时恢复。恢复期间遇到人为改动或损坏备份会停止，保留证据供处理。

M2 的旧 fixture 清理、superseded 公开展示策略、内容准确率和叙事质量仍待执行；M3 定时运行、审核 PR 与部署也未在本次实现。
