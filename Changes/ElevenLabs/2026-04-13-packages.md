# Packages

**ElevenLabs** · 2026-04-13 · [[Themes/voice|Voice and Audio]] · Launch · [Official source](https://elevenlabs.io/docs/changelog/2026/4/13) · from [[Releases/ElevenLabs/elevenlabs-2026-04-13-2026-04-13-a9d3ca3b|ElevenLabs updates — 2026-04-13]]
<!-- chronolog:end -->

<!-- chronolog:begin region="evidence" -->
> [@elevenlabs/client@1.2.0](https://github.com/elevenlabs/packages/releases/tag/@elevenlabs/client@1.2.0) - Fixed `getInputVolume()` and `getOutputVolume()` returning 0 in React Native by adding native volume providers using LiveKit's RMS and multiband FFT processors. `getInputByteFrequencyData()` and `getOutputByteFrequencyData()` now return data focused on the human voice range (100-8000 Hz), which is more useful for voice visualization, and on web `getInputVolume()` and `getOutputVolume()` are also computed from this range.
>
> [@elevenlabs/react@1.1.0](https://github.com/elevenlabs/packages/releases/tag/@elevenlabs/react@1.1.0) - Fixed `startSession` errors being swallowed instead of surfaced via `onError` in `ConversationProvider`. Previously, when `Conversation.startSession()` rejected (e.g., "agent not found"), the UI would get stuck in "connecting" with no error feedback.
>
> [@elevenlabs/react-native@1.1.0](https://github.com/elevenlabs/packages/releases/tag/@elevenlabs/react-native@1.1.0) - Updated to `@elevenlabs/client@1.2.0` and `@elevenlabs/react@1.1.0` with native volume provider fixes.
>
> [@elevenlabs/convai-widget-core@0.11.3](https://github.com/elevenlabs/packages/releases/tag/@elevenlabs/convai-widget-core@0.11.3) - Fixed transcript message ordering in voice mode where agent responses could appear before user messages.
>
> Source: https://elevenlabs.io/docs/changelog/2026/4/13
