# 60 other changes in v2026.10.6

**OpenClaw** · 2026-10-22 · Other changes · Digest · [Official source](https://docs.openclaw.ai/releases/2026.10.6) · from [[Releases/OpenClaw/openclaw-2026-10-22-v2026-10-6-56379f53|v2026.10.6]]
<!-- chronolog:end -->

<!-- chronolog:begin region="evidence" -->
## Changes in this digest

> This is a patch release with no new features. It contains urgent fixes for problems that could stop OpenClaw from installing, updating, or starting, plus smaller reliability fixes.

> Skill setup now only checks for the installers your selected dependencies actually need.

> Hermes and Claude imports no longer touch instruction files that aren’t valid UTF-8. To import one, back up the original, convert a copy to UTF-8, and run the import again. See Hermes migration .

> Hermes migration previews now tell you which files they couldn’t read. Fix the access problem and rerun the preview before applying it.

> Setup now tells you why a Gateway restart you asked for failed.

> The Sessions view now shows how long the current helper has been running while follow-up work continues.

> Gateway shutdown now waits for pending cleanup to finish, and gives Windows more time to confirm it has stopped. See restart recovery .

> Backup cleanup can now continue after you repair a btrfs filesystem. See btrfs recovery and update cleanup .

> After a manual upgrade, openclaw status no longer suggests an outdated update that could undo the Gateway version you chose. Other update and rollback warnings still appear. See status guidance .

> Updates now continue, with a visible warning, if saving a copy of the original install fails. Database snapshots needed for rollback are still required. See update repair and recovery .

> Configuration repair no longer changes your files if it can’t save a copy of the originals first. Fix the reported lock or storage problem, then retry. See configuration troubleshooting .

> Doctor now accepts duplicate transcript headers that only differ by timestamp. Original archives are kept, and transcripts with conflicting content are still refused. See Doctor's session checks .

> Doctor no longer changes workspace notes that aren’t valid UTF-8. To process one, back up the original, convert a copy to UTF-8, and retry.

> Uninstalling on Linux now reloads your user services after removing the OpenClaw service. If that reload fails, run systemctl --user daemon-reload . See Gateway service commands .

> Uninstall now stops instead of continuing if it can’t check a workspace that should be kept.

> Doctor can now repair an empty database that a native app created first, and tells you if a database you need still isn’t usable. See database recovery .

> Older Mac profiles that couldn’t start because their database was missing its deletion-history table can now start again and get your saved conversations back. You need a verified full backup of the database and its WAL file first. Items that were waiting to be deleted may come back if their deletion record was lost. See database integrity and recovery .

> Gateway cleanup warnings now tell you what actually went wrong.

> Restart requests on Mac now tell you when the restart helper couldn’t be launched.

> Saved shutdown diagnostics now include more useful process information, with sensitive details removed.

> When the Gateway won’t start because of a file-ownership or cleanup problem, it now says so instead of suggesting OpenClaw isn’t installed.

> Update status no longer keeps showing migration warnings after you’ve fixed the problem. See SQLite maintenance .

> Doctor now waits for earlier database writes to finish before repairing the database. If a check reports the database is busy, just retry; being busy isn’t a reason to restore it.

> Database cleanup that’s already running can now finish when maintenance shuts down.

> CLI state commands now stop before doing anything if the selected state or the running Gateway changed underneath them.

> If you interrupt an update, it now finishes cleaning up and keeps a recovery record for that run.

> Delivery warnings now say more clearly which messages were abandoned and which storage problems caused it. Check the conversation before resending anything.

> Messages waiting in the queue, and replies still being written, now survive a Gateway restart. If recovery is blocked, use Resume in new session in WebChat, or start a new or reset conversation in another app. See sessions and recovery .

> Channel errors now tell you which storage problem needs fixing.

> Telegram now follows your IPv4-first setting when IPv6 is broken, and can retry a send that clearly timed out. Sends with an unclear result aren’t repeated.

> Nostr pairing notifications now report a failure when they can’t reach the Gateway. Use an app connected to the Gateway if you need the notification; starting the Gateway alone doesn’t connect the standalone CLI.

> Channels that recover now clear their old restart warnings.

> Skill dependencies can now unpack archives from generic download links, using the file name the server provides.

> New Peekaboo installs now use the maintained Homebrew source.

> Finding and reading remote skills can now recover from a brief interruption while pairing changes. This only retries reads and never gets around revoked access.

> Workshop now keeps your original files if both restore and rollback fail.

> The Mac app now tells you how to update when its bundled worker isn’t compatible.

> Mac companion commands now respect longer response timeouts you ask for. If an action times out, check whether it happened before trying again.

> Node-worker control errors now tell you why they failed.

> Managed Codex startup now keeps on-request approval and allows side questions.

> Managed DeepSeek sessions through OpenRouter can now recover valid tool requests wrapped in provider markup. Incomplete requests are hidden, not run.

> DeepInfra and OpenRouter speech requests now get up to 120 seconds by default instead of 30. Timeouts you set yourself still apply.

> If Codex rejects a message because its saved conversation is missing on the server, OpenClaw can now restore the history and try once more. If the history can’t be restored, the message wasn’t sent: reconnect the conversation to a Codex session and resend it. See Codex session commands .

> If a scheduled job’s failure alert is refused before it’s sent, the job’s owner now gets an in-app notice instead. Alerts with an unclear delivery result aren’t sent twice. See scheduled-job delivery .

> A targeted heartbeat now delivers its queued background-task result to the right conversation, even when regular heartbeats are off. See system commands .

> New scheduled follow-ups can now continue work you already approved in the same conversation. Recreate existing jobs to get this behavior.

> Eligible ACP coding sessions now resume once after a Gateway restart. Finished sessions start fresh.

> OpenShell now keeps your local and remote workspace views when a read fails.

> 1Password errors when reading secrets now include useful details, with sensitive values removed.

> Finished Codex helpers now retry cleaning up leftover status subscriptions after a temporary failure.

> Adds remediations for the eMudhra certificate compromise. OpenClaw now requires Node 24.22.1 or newer on Node 24, or 26.12.1 or newer on Node 26, because older Node builds may still trust the affected certificates. If you manage Node yourself, upgrade before starting OpenClaw. Docker images and installers already use the patched versions.

> Setup now asks for approval again after an earlier approval expires or is cancelled. If an approved change fails, check your settings and status before retrying.

> If you turn on continuation instruction skipping, workspace instructions are no longer resent on every follow-up once they’ve been delivered. It’s off by default. See workspace instructions .

> /new and /reset now keep your managed project checkout and working folder, so unfinished files are still there.

> Invalid tool arguments are now labeled as failures instead of policy blocks. Real policy denials still show as blocked.

> Tool calls that time out now stay clearly marked as blocked, and their completed results and attachments are kept.

> DNS tools no longer change zones they can’t read.

> Cloning a managed project no longer overwrites an existing folder it can’t inspect. It only clones when the folder doesn’t exist.

> A slow Stop request now stays accepted even if its reply times out, and repeated cancel notices no longer undo a confirmed stop. If Stop is still settling, check the session’s status before trying again. See session status and control .

> openclaw gateway suspend --json now always prints valid JSON, even when the Gateway is busy.
