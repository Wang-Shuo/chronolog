> GitHub hover previews, repository searches and publication account options can show a previous result while refreshing, clearly marked as stale. Publication still checks current access before it proceeds.

> An accepted PR publication request can remain pending through a temporary session-access interruption. Check the original request's result rather than sending a duplicate.

> A bound Codex conversation can resume its original thread after the Codex service restarts. An input is retried only when the service confirms it was rejected before acceptance.

> Managed local Codex conversations can recover from a provider error or refresh their settings without replacing their history or interrupting another conversation's work.

> Binding a conversation to Codex no longer fails just because its next reply is waiting to start. If the source conversation is already working, let it finish or stop it before binding.

> Switching away from Claude CLI and back no longer repeats the same question.

> A history-free run that reaches its output limit now stops rather than sending the same request again.

> Shortening a conversation now keeps each tool result paired with the call that produced it.

> Web fetch now keeps more numbers, code examples, headings and list boundaries intact, so retrieved pages are less likely to arrive garbled. It also excludes a recognized form of visually hidden text.

> Authorized operators can still view and revoke standing grants on the Approvals page when its approval history fails to load, as long as the grants service is available.

> Diagnostics exports now keep the destination you entered, including meaningful spaces, and patch views retain trailing whitespace and the final newline.

> Scripts using experimental claws remove --json now receive a JSON error for two invalid cleanup-option combinations instead of only a plain-text error.

> A refused database opening no longer unnecessarily interrupts other readers, and affected operations can retry.

> Scheduled maintenance keeps its timing after a clock correction, and a failed worker start no longer leaves its database in use.

> Gateway readiness checks now wait for the final startup work to finish instead of reporting ready while it is still running.

> Saved Gateway connections in the Linux app keep their pairing when you switch between them or restart the app. Removing and re-adding a Gateway starts a fresh pairing.

> The Mac Connection screen reports the actual local Gateway version and offers update or repair when needed, without proposing a downgrade for a healthy newer installation.

> The Mac app is less likely to leave a healthy Gateway on a recovery screen after an update, and Retry can repair an incomplete installation. Direct connections with a learned certificate pin can reconnect after a trusted renewal for the same host; explicit pins remain fixed.

> Windows source and package updates avoid more path, backup and service failures, and an early failed source update can restore a verified previous build. Some repairs must already be in the updater performing the update; an older broken updater may still need manual recovery.

> Managed Linux desktops can start when a hidden display socket occupies the expected display, and host commands launched from an AppImage no longer inherit its conflicting library path.

> On affected Linux filesystems, startup and Doctor can recover when a fast file copy is refused instead of failing outright. Credentials in covered process-cleanup errors are masked before the error is saved or shown.

> Update preparation refreshes the selected target before you confirm, and supported package and Bun installs handle more interrupted or unusual first-upgrade paths.

> Supported update recovery can resume more updates blocked by temporary contention or abandoned work, while refusing to repeat steps whose outcome is uncertain. An older broken updater may still need the documented manual recovery path.

> Doctor and common configuration commands do less repeated scanning, and warnings better distinguish a real repair problem from an unchanged or already-settled one.

> Package and source updates are less likely to lose their launcher or running updater files during replacement, and verified early failures can leave the previous Gateway usable. Several protections must already be in the installed updater before that attempt begins.

> Supported backups and rollback can restore more verified older archives and keep recovery copies when an update cannot safely undo database changes.

> Installation and Doctor errors now point to the failed step and a more useful retry or repair path. If your configuration includes other files, review a proposed single-file repair before accepting it because it can revert settings from those included files.

> Doctor no longer blocks recovery cleanup with a false warning that the database changed during its inspection.

> Doctor's btrfs repair no longer leaves verified migration backups permanently ineligible for normal cleanup.

> After a session database is replaced, new work refuses an old database location instead of silently using the wrong conversations. If a write's result is uncertain, check what was saved before retrying.

> Stock Bun now requires 1.4.4 or newer; the pinned OpenClaw Bun fork remains supported. Bun’s certificate fix is partial, so use patched Node when current rejection of compromised certificate keys is required. Read-only Kubernetes deployments also need the writable-cache setting with their image update to start successfully.

> Logs now repeat fewer warnings for an already-known conversation problem, while keeping current failures visible. This does not restore turns that were previously blocked.
