# 18 other changes in v2026.10.4

**OpenClaw** · 2026-10-16 · Other changes · Digest · [Official source](https://docs.openclaw.ai/releases/2026.10.4) · from [[Releases/OpenClaw/openclaw-2026-10-16-v2026-10-4-c8c204e0|v2026.10.4]]
<!-- chronolog:end -->

<!-- chronolog:begin region="evidence" -->
## Changes in this digest

> Dashboard connection. Open dashboards can stay connected when a busy Gateway delays its check-in messages, avoiding unnecessary reconnects. Requests still have their own timeouts.

> Sleep and clock changes. Fixed unnecessary interruptions after computer sleep or backward clock changes, with clearer restart guidance when OpenClaw loses access to its saved state.

> Gateway shutdown. Stopping or restarting OpenClaw no longer hangs on stalled conversation indexing, and pending session updates can finish before connected clients close. Saved transcripts remain available after a restart .

> Update snapshots. After installing 10.4, later upgrades avoid false warnings that an unchanged database changed while its recovery copy was made. Real later changes can still prevent automatic restoration .

> Updates after data migration. Update checks avoid false verification failures after data migration. Status also stops repeating a saved restart warning once the running Gateway reports the expected version. See rollback and recovery .

> Temporary update files. Doctor and updates can remove abandoned temporary update directories despite unrelated system processes, including ordinary Linux systemd user sessions. Directories still used by live OpenClaw processes remain protected.

> Temporary disk use. Update checks reuse eligible prepared database copies instead of duplicating them again, and give clearer retry guidance for space failures.

> Update failure guidance. Snapshot-preparation failures now point to the snapshot step that failed, instead of runtime verification that never ran.

> Scheduled work during updates. After installing 10.4, later update checks give scheduled jobs and cleanup a chance to save while the updater waits to record its progress.

> Delegated update repair. Delegated repair work spends less time rechecking permissions and can reach repair tools before timing out.

> Offline app-owned repair. Standalone Doctor can repair the same account's configuration and state when an app-owned Gateway is verified offline. Restart or update through OpenClaw.app afterward.

> Telegram polling. Fixed a polling-worker startup failure that prevented Telegram messages from arriving in affected installations.

> IRC replies. Long replies containing Chinese, Japanese or Korean text and emoji arrive without losing forwarded chunks.

> Feishu settings reload. Feishu DMs keep receiving replies when a settings reload overlaps a reply already underway, without needing an OpenClaw restart.

> Long streamed replies. Long replies that use OpenClaw's reply-to-message instructions can arrive with less delay, while keeping their text and intended reply target.

> Mac app recovery. The updated Mac app preserves an already-newer managed Gateway during setup and recovery, and can restore its missing Node background service using that installation.

> Claude CLI conversation history. Switching between a messaging channel and web chat keeps the latest history in the same Claude CLI conversation , preventing new branches that miss intervening actions.

> Repeated historical warnings. Later runs of a conversation stop repeating warnings for work already marked as blocked, making old failures less likely to look new. The blocked work is not repaired, and its records remain.

Source: https://docs.openclaw.ai/releases/2026.10.4
